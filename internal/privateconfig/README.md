# 個人用 LLM 設定

`Open(dir)` の `dir` には、OS が提供する現在のユーザーのローカルアプリデータ領域を渡す。共有ワークスペースやソースフォルダには置かない。

```
<user-local-app-data>/OneByOne/private/
  master-key.json
  .init.lock
  .connections.lock
  llm-settings/
    <SHA-256(global-registry-key)>.json
```

- 接続一覧はスキーマ2で保存する。読込時に形式・復号・内容検証が失敗した場合は、その接続一覧の暗号化ファイルだけを破棄し、空の一覧から再登録できる。キー、ワークスペース設定、他のファイルは保持する。アクセス権や入出力のエラー、シンボリックリンクなどの不正な保存先はエラーとして返し、削除しない。
- 初回に `crypto/rand` で 32 バイトのキーを生成する。GUID やパスワードから派生させない。
- 名前付き接続の一覧、接続先、モデル、認証方式、API キー、OAuth の設定・アカウント・MSAL トークンキャッシュを1つのレジストリとして AES-256-GCM で暗号化する。保存ごとに新しい96ビットのランダム nonce を使い、形式バージョンとレジストリ識別子を追加認証データに含める。改ざんや異なる識別子での読込は復号エラーになる。ハッシュ化だけで保存する方式ではなく、API 呼び出し時には Go 側のメモリで復号する。
- Windows ではマスターキーも現在のユーザーの DPAPI で保護する。macOS/Linux ではマスターキーは所有者のみ読み書き可能なファイル (`0600`) とディレクトリ (`0700`) で保護する。
- macOS/Linux のマスターキーと暗号化設定を両方取得できる人は復号できる。同じユーザーとして動くプロセスや、管理者権限から守る仕組みではない。macOS Keychain は使用しない。Windows のデータも別のユーザーや別の PC へコピーしてそのまま使用することを想定しない。
- キーを失った場合、既存の暗号化設定は復元できない。キーや設定の破損時に平文へフォールバックしたり、既存の暗号文がある状態でキーを再生成したりしない。
- 保存は同一ディレクトリ内の一時ファイルを同期してから置換する。初回キー生成と接続レジストリの読込・更新は、それぞれ OS ロックで直列化する。`UpdateConnections` は最新内容の読込から置換完了までロックを保持し、複数プロセスが別の接続を追加しても取りこぼさない。シンボリックリンクや通常ファイル以外の保存先は拒否する。
- 秘密情報をログやエラー文字列に出さない。テストは一時ディレクトリと架空の API キーのみを使用する。

## OAuth キャッシュの扱い

Azure OAuth は `internal/azureauth` が MSAL Go を通して取得したキャッシュを `OAuthCache` として保存する。キャッシュには更新トークンが含まれ得るため、API キーと同じ秘密情報として扱う。`OAuthAccountID` で本人のアカウントを固定し、`OAuthGeneration` はサインイン・サインアウト・接続先や認証設定の変更時に更新する。通常のトークン更新では世代を変えない。

エンジンは各 API リクエスト前に最新の暗号化レジストリを読み、保存済みのアカウントでトークンを取得する。更新されたキャッシュの保存時も接続情報と世代を照合し、古い更新処理でサインアウトを取り消したり、別の接続・アカウントの認証を上書きしたりしない。サインアウトは当該接続のキャッシュとアカウントを削除するローカル操作で、Microsoft 側のトークン失効やブラウザーのログアウトは行わない。

UI に返すのはテナントID・クライアントID・表示用アカウント名・サインイン状態で、アクセストークン・更新トークン・キャッシュは返さない。ワークスペース、キュー、ルールパッケージ、結果レポートにも認証キャッシュを保存しない。OAuth では環境変数や API キーへフォールバックせず、更新できない場合は再サインインを案内する。接続の導入手順は[Azure OAuthの設定](../../docs/azure-oauth.md)を参照。

参照: [Go AES-GCM](https://pkg.go.dev/crypto/cipher#NewGCMWithRandomNonce)、[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
