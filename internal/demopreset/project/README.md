# Parcel Desk — OneByOne 実践デモ

架空の配送・請求管理アプリ「Parcel Desk」が、利用中のSDK「Parcel Kit」から後継の「Parcel Client」へ切り替えるデモです。制御フロー、リソースの所有権、処理順序、エラー伝播を変更します。単純なAPI名の置換だけでは正しく移行できません。外部通信・実際の個人情報・インストールする依存パッケージはありません。

## 使い方

1. 新しいワークスペースの作成ダイアログで「デモプロジェクトを作成する」を選び、保存先を指定します。プロジェクトの生成とGitの初回コミットまで自動で行われます。
2. ワークスペースの作成を完了すると、共通3件・個別10件のデモルールも自動で設定されます。「対象フォルダ」でパス、「ルール」で内容を確認します。
3. 「実行設定」を開くと対象が自動抽出されます。共通ルールがあるため `src/**/*.js` の23ファイルすべてが候補になり、初回は全件が選択済みです。登録済みLLM接続とキュー・実行結果の保存先を指定し、処理しないファイルのチェックを外して対象を確定します。実際のAI利用・料金・制限は通常の処理と同じです。
4. 「確認」で選択済みファイルと候補ルールを確認し、「実行」を押します。この画面では再抽出やチェック変更を行いません。対象や設定を変える場合は「実行設定」へ戻ります。
5. 「結果確認」の上部で現在の状態と進捗を確認し、必要なら処理を停止します。一覧のファイルをクリックすると差分、適用ルールをクリックすると内容が開きます。検証結果、保留理由、試行履歴などは必要な項目を開いて比較します。

プロジェクト全体は28ファイルです。`src/orders/`、`billing/`、`jobs/`、`ui/`、`shared/`、`workflows/` に23ファイル、`lib/` にParcel Kit・Parcel Clientの2ファイル、README・package.json・.gitignoreが各1ファイルあります。`lib/` は対象外なので、移行途中でも新旧両方の呼び出し先が存在します。

## 中心となる10の変更

| ファイル | ルール | 判断・構造変更のポイント |
| --- | --- | --- |
| `orders/place-order.js` | R101 | 成功/失敗の両方でcloseするfinallyを追加。通知失敗をコミット失敗と混同しない |
| `ui/live-orders.js` | R102 | 購読ハンドルを画面が所有。部分初期化失敗や停止時に自分の分だけ解除 |
| `jobs/export-orders.js` | R103 | 同期全件取得をページ単位のawaitループへ。収集後に重複排除・集計・全体ソート |
| `billing/invoice-export.js` | R104 | writeの後に必ずflushをawait。保存済み進捗や完了を通知するタイミングも変更 |
| `jobs/process-shipment.js` | R105 | 受信直後のackを削除。永続化成功後にcomplete、失敗はretry、終了時close |
| `billing/payment-request.js` | R106 | 生ペイロードのJSON化・debug分岐・機密の記録を削除。許可した項目だけ監査に残す |
| `jobs/reconcile-payments.js` | R107 | 最初のawaitより前に深いコピーを固定。試行ごとの変異を廃止し同じ冪等キーを再利用 |
| `orders/bulk-reserve.js` | R108 | 全件検証と予約を2段階に分離。不正入力が1件でもあれば副作用ゼロ |
| `billing/settle-invoice.js` | R109 | callbackの入れ子を順次awaitに変換。capture失敗時だけvoidし、元の例外を保持 |
| `shared/runtime-options.js` | R110 | 秒→ミリ秒とオブジェクト階層変更。null・undefined・0の異なる意味を保持 |

10件の中心シナリオはそれぞれ約40〜65行です。ルールにはAPIの契約・適用条件・保留条件と、対象ファイルとは別用途の短い変更例を収録しています。対象ファイルの全文や完成コードは載せていません。例をそのまま転記しても対象の業務処理は完成しないため、既存の検証・集計・通知・例外処理を読み、どこへ変更を組み込むか判断する必要があります。

たとえばページ走査の小さな例から全体ソートを伴うエクスポートへ応用したり、単一購読の解放を複数購読の部分初期化失敗へ広げたりします。API実装は `lib/parcel-kit.js` と `lib/parcel-client.js` で確認できます。Parcel Kitを使う呼び出し側には、早すぎる確認応答や個人情報の記録といった、ルールで明示して改める挙動も含みます。APIは `TransactionManager`、`RecordDirectory` など通常の用途を表す名前です。変更の要否は名前に付いた新旧の目印ではなく、ルールに定義したAPI契約と周囲の処理から判断します。

## 複合ケース・変更不要・保留

- `workflows/dispatch-cycle.js`: 約460行の配送サイクル管理。全13ルールが実際の変更対象です。全件収集と顧客別の配送計画、在庫予約、請求決済と手数料送信、出荷ラベル保存、履歴保存、レポート公開を一連の処理として扱い、進捗画面の購読も所有します。共通ルールでは状態変数の宣言、nullish既定値、import整理が必要です。個別ルールでは購読・トランザクションの解放、ページ走査、保存後の通知・確認応答、機密記録の削除、入力固定・冪等再試行、全件検証、決済補償、設定の単位変換が組み合わさります。名前を置換するだけでは、前後の順序や外部コールバックによる入力変更に対応できません。
- `orders/order-summary.js`、`ui/notification-model.js`: 共通ルールだけの対象。再代入・クロージャを読んだvar整理、nullish既定値の整理。
- `jobs/order-index.js`: ページ走査への変更と共通ルール。完全な索引を一度だけ保存する順序を保持。
- `billing/settlement-audit.js`: バッファflushと機密記録削除を組み合わせる。結果のreaderが読む前にflushが必要。
- `shared/money.js`、`ui/status-labels.js`、`orders/order-validator.js`、`jobs/schedule-window.js`: 既に適切なコード。ルールに該当しなければ `skipped` が想定されます。
- `ui/external-list-hook.js`: 同期結果を要求する外部ホスト。async化の合意が必要なら `needs_human`。
- `shared/host-transaction.js`: 所有権と寿命が外部ホストにまたがる。closeの責任を決められなければ `needs_human`。
- `jobs/dynamic-provider.js`: 外部で決まる操作名と同期契約。移行範囲を確定できなければ `needs_human`。
- `billing/opaque-config.js`: 外部オプションの単位・nullの意味が未定義。推測が必要なら `needs_human`。

結果はAIの判断や設定で変わり、固定されていません。安全に修正・検証できれば `done`、不要なら `skipped`、未解決の契約があれば `needs_human` になります。`pending` と処理中の表示は進行状態です。`failed` は実際の検証・通信等の失敗で現れ、再試行で解消することもあります。失敗や全ステータスを強制する仕掛けはありません。

大型ケースで10件の個別ルールとSDKを読む余地を確保するため、このデモの上限は1試行20ターン、1回の出力16,384トークンです。大型ケースを外して小さなケースだけを試すこともできます。どのケースも、対象の完成コードをルールに含めていません。

## 検証の範囲

標準はOneByOneの旧参照残存・変更範囲検査と `git diff --check` です。JavaScriptの構文・型・振る舞いは、この標準設定では保証しません。flush忘れ、早すぎるcomplete、同じ処理の二重実行などは旧名が消えているだけでは検出できず、`done` にも残り得ます。結果の差分を確認し、必要に応じて検証コマンドを追加してください。

Node.jsはデモ作成・標準実行の必須条件ではありません。Node.js 18以降がある場合は任意で単一ファイルの構文を確認できます。

```sh
node --check src/jobs/export-orders.js
```

これは振る舞いのテストではありません。`demoState` にローカルの記録と失敗注入フラグがあるため、利用者が順序・重複・解放を検証するテストを作ることもできます。フラグは初期状態ですべてfalseで、OneByOneが自動で失敗させるものではありません。

AIの修正は専用のGit作業コピーで行われます。元のフォルダだけでなく、結果画面の差分と成果物を確認してください。
