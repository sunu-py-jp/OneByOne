# OneByOne デスクトップUI

React / TypeScript / Viteによる画面です。実際のファイル操作・Azure通信・永続化は、Wailsの `window.go.main.App` を経由してGo本体が実行します。画面から任意のシェルやファイル書き込みは実行しません。

```sh
npm ci
npm run typecheck
npm run build
```

生成先は `frontend/dist/` です。Wails本体がこのディレクトリを埋め込みます。フォントや画像を外部CDNから取得せず、インストール済みのシステムフォントを使用します。

## 開発・画面プレビュー

```sh
npm run dev
```

`http://127.0.0.1:5173/?demo=1` は明示的な画面プレビューです。すべてのデータがサンプルであることをバナーに表示し、AIの実行・ファイル操作・設定保存はできません。一覧の検索・フィルタ・ページ送り・ルール閲覧・差分・検証結果・試行履歴・設定カテゴリ・ログ表示は操作できます。

通常のブラウザでクエリなしのURLを開いた場合は、デスクトップ接続がないことを表示します。ブラウザ上で本番処理を動かすHTTPサーバーは提供していません。

## 画面からの操作

1. 対象フォルダと `rules/` を選択し、設定を保存する。旧シンボルによる抽出・検査を使う場合は「接続・設定 → 対象・検証」で `patterns/legacy-symbols.txt` のパスを指定する。
2. 「対象を抽出」でJSONLを作成する。ファイル本文から抽出した候補ルールが一覧に表示される。
3. Azureの接続先・デプロイ名・認証情報を設定する。APIキーまたは手動取得したEntra IDアクセストークンに対応する。認証情報は画面のローカルストレージなどへ保存しない。
4. 「20件で試す」または「移行を実行」で処理する。実行中は1.5秒ごとにGo本体の状態を取得する。設定の未保存変更はポーリングで上書きしない。
5. ファイルを選択して差分・検証結果・試行履歴を確認する。履歴は配列のインデックスで指定し、過去の失敗も参照する。
6. チェックボックスで選択したファイル、要確認のファイル、または特定ルールを適用したファイルを待機中に戻して再試行できる。適用ルールはAIの報告であることと、機械検証の結果を分けて表示する。
7. 「結果を出力」でGo本体が生成するレポートを保存する。「作業コピーを開く」で変更先のフォルダを確認する。元のソースへの自動反映は行わない。

既存のJSONLは「接続・設定 → 対象・検証」から読み込めます。初期画面には実際のGitサンプルを一時ディレクトリに作成する「サンプルプロジェクトを開く」があります。これは画面プレビューと異なり、Azure接続後に実際の修正を実行できます。

## 検証記録

- `npm run build`: TypeScriptのstrictチェックとVite本番ビルド。
- ブラウザで、候補ルール表示、状態フィルタ、失敗ファイルの検証結果、試行履歴から差分への移動、ルール本文、Azure設定、処理上限、ログドロワーを確認。
- プレビュー画面で実行・設定保存などの変更操作が無効になることを確認。
- 10,000件規模の一覧は200件ごとにページ分割。検索と状態フィルタは全件に適用する。

実際のAzure接続、ネイティブファイル選択、Windows/macOSの配布物検証はGo/Wails側の検証と組み合わせて行います。
