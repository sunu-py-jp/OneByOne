# Windows修正と再検証（2026-09-24）

[前回の検証](windows-validation-2026-09-23.md)で見つかった問題への対応記録。

## 修正内容

- 保存時のWindows APIを`MoveFileExW`からGoの`os.Root.Rename`に変更。スナップショットの読込側も置換を許可するハンドルを使い、読み込み中の旧内容を保ったまま新しい内容を公開する。
- 外部のエディターなどが一時的に保存を妨げる場合は最大2秒再試行する。競合が続く場合はエラーを返して元のファイルを保持し、一時ファイルを片付ける。削除してから書き直す処理は使わない。
- 編集ロックを`workspace-locks/<ID>/`へ移動。Windowsでワークスペースを退避・復元するときも、ワークスペースとルールの編集ロックを保持する。削除済みワークスペースの再生成を防ぐ検査も維持する。
- ワークスペース複製時に、コピー先のフォルダを明示的に作成。ロック取得時の副作用に頼らないようにした。
- 対象フォルダ変更時のアプリ内部の相対パスをOS非依存にし、Windowsの区切り文字で拒否される問題を修正。
- テストではディレクトリの最新情報をハンドルから取得。Windowsの列挙キャッシュによる更新日時の見かけ上の変化を避け、内容・サイズ・権限・時刻の比較は継続する。
- ロック中の空ファイルはサイズとメタデータで検証。所有者情報を読むテストはロック解放後に読み、OSの排他制約に合わせる。
- Nodeテストの相対リンク比較でWindowsの区切り文字を正規化。絶対リンクに変わっていないことも確認する。
- 開発用Goテストの時間制限をWindowsではパッケージごとに30分とし、`npm test -- --timeout 45m`で指定できるようにした。アプリのAI処理上限には影響しない。

ロックの移行中も旧版との同時編集を防ぐため、`setting.json`をVersion 2へ更新する。Version 1を編集する際は新旧両方のロックを取得し、最新の設定を読み直してから形式を更新する。旧版が編集中の場合は設定を変更せず閲覧専用とする。既存の設定内容は引き継ぐが、更新済みワークスペースは旧版では開けない。

## 再検証

Windows 11 ARM64のVM上で、既存のGo 1.27.1／Node.js 22.23.2／Wails 2.15.0を使い、amd64版を検証。アプリ実行用ソフトの手動追加インストールは行っていない。

| Windows 削除・復元・デモ・差分表示関連のテスト | 成功。編集ロックを維持した退避と復元、前回の更新日時比較失敗も解消 |

| Mac GUI・CLIビルドとスモーク | 成功。同梱Git/rg、デモ作成、対象抽出、状態復元を確認 |

この検証は実LLMへ送信しない。物理x64端末、WebView2未導入環境、Setupのインストール・更新・アンインストールは今回の修正確認には含めない。

GUIは検証専用の設定フォルダと、Windows・System32だけのPATHで起動した。削除したのは検証用に複製したワークスペースのみで、元のデモと対象ソースは残している。

Windowsではengineテスト本体が約21分で終了した後も、Goコマンドの終了まで待機が発生した。約96MBのテスト入力ログとGoの実装から、成功時の結果キャッシュ生成が主因と判断している。これは開発用検証の所要時間で、アプリによるAI処理の時間ではない。

## コマンドと証跡

Macでは既存のGo/Wailsの場所を`GO_BINARY`・`WAILS_BINARY`で指定し、次を実行した。

```sh
npm test -- --race
npm run build
node scripts/smoke-package.mjs build/bin
```

Windowsも同じ開発コマンドを使用した。検証専用フォルダに準備済みの開発ツールを使い、OS共通のPATHやアプリ実行環境へ追加インストールしていない。

```powershell
npm.cmd run build -- --platform windows/amd64
node.exe scripts/smoke-package.mjs build/bin
npm.cmd test
```

ログは`build/validation/windows-20260924/`へ端末内の記録として保存し、Git管理から除外した。`validation-summary.json`には最終実行の3工程すべての終了コード0を記録している。`source-final-manifest.json`はWindowsへ転送した修正ソースのSHA-256一覧で、転送先との一致を確認してからビルドした。`intermediate/`は複製の修正を反映する前の全体テストの記録。

Windows生成物は`%USERPROFILE%\OneByOneValidation\20260923\source\build\bin`。Mac生成物は`build/bin/OneByOne.app`と`build/bin/onebyone`。
